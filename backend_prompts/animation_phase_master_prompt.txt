## VISUAL ANCHOR SYSTEM (NEW — CRITICAL)

### WHAT IS A VISUAL ANCHOR?

A Visual Anchor is a concrete, animated visual element that makes
an abstract concept TANGIBLE. It is not decoration — it TEACHES.

VISUAL ANCHOR TYPES:

TYPE 1 — GEOMETRIC ANCHOR:
  Rectangle, triangle, circle, number line, coordinate plane
  USE WHEN: concept involves shape, area, perimeter, angle, distance
  EXAMPLE: "Area = length × width" → animated rectangle with grid overlay

TYPE 2 — DIAGRAM ANCHOR:
  Tape diagram, bar model, balance scale, Venn diagram, tree diagram
  USE WHEN: concept involves part-whole, comparison, proportion, probability
  EXAMPLE: "3 over 5 of 20" → tape diagram with 5 blocks, 3 highlighted

TYPE 3 — TRANSFORMATION ANCHOR:
  ReplacementTransform, morphing shapes, ValueTracker animations
  USE WHEN: concept involves change, cause-effect, variable relationships
  EXAMPLE: "doubling the radius quadruples the area" → circle growing with
           area value updating in real-time

TYPE 4 — ANNOTATION ANCHOR:
  Color highlights, arrows pointing to parts, brace labels, underlines
  USE WHEN: concept involves identifying parts of an expression or figure
  EXAMPLE: "the numerator tells us how many parts" → numerator highlights
           orange with arrow labeled "parts taken"

TYPE 5 — SEQUENTIAL BUILD ANCHOR:
  Step-by-step expression building, equation balancing
  USE WHEN: concept involves procedure, algorithm, derivation
  EXAMPLE: "first multiply, then add" → expression builds left to right
           with each operation appearing on its bookmark

TYPE 6 — TEXT-BASED ANCHOR (FALLBACK):
  Concept card, bullet points, labeled expression with color coding
  USE WHEN: concept is purely definitional, no spatial/visual metaphor exists
  EXAMPLE: "A polynomial is an expression with variables and coefficients"
           → concept card with key terms in ORANGE_HL

### VISUAL ANCHOR DECISION TREE (MANDATORY — Step 0)

For EVERY sentence in the transcript, evaluate:

```
SENTENCE: "[transcript sentence]"
  │
  ├─ Does it describe a SHAPE or SPATIAL relationship?
  │   YES → TYPE 1 (Geometric Anchor)
  │
  ├─ Does it describe a PART-WHOLE or COMPARISON?
  │   YES → TYPE 2 (Diagram Anchor)
  │
  ├─ Does it describe CHANGE or CAUSE-EFFECT?
  │   YES → TYPE 3 (Transformation Anchor)
  │
  ├─ Does it IDENTIFY PARTS of something?
  │   YES → TYPE 4 (Annotation Anchor)
  │
  ├─ Does it describe a PROCEDURE or SEQUENCE?
  │   YES → TYPE 5 (Sequential Build Anchor)
  │
  └─ NONE of the above?
      └─ TYPE 6 (Text-Based Anchor — concept card / bullet)
```

✅ EVERY sentence gets AT LEAST one visual anchor
✅ Prefer Types 1-5 (visual) over Type 6 (text) always
✅ If a sentence CAN have a visual anchor, it MUST — text fallback forbidden
❌ NEVER leave a sentence with NO visual on screen
❌ NEVER use Type 6 when Types 1-5 are possible

### VISUAL ANCHOR PLACEMENT RULES

ANCHOR SLOT PRIORITIES (where anchors live on screen):

```
Concept phase:  SLOT_FIGURE_C (ORIGIN)     — anchor fills center
                SLOT_CONCEPT  (UP * 0.5)   — text card above anchor
                SLOT_CAPTION  (DOWN * 2.5) — label below anchor

Question phase: SLOT_FIGURE_C (ORIGIN)     — anchor IS the question figure
                SLOT_QUESTION (UP * 2.5)   — question text above

Solution phase: SLOT_FIGURE_R (RIGHT * 3)  — anchor stays visible
                SLOT_STEPS    (LEFT * 3.5) — steps reference anchor
```

ANCHOR COEXISTENCE (what can appear WITH an anchor):

```
Geometric anchor + dimension arrows     ✅
Geometric anchor + grid overlay         ✅
Diagram anchor + brace labels           ✅
Transformation anchor + value display   ✅
Annotation anchor + expression          ✅ (annotation ON expression)
Text anchor + concept card              ✅ (text IS the anchor)
Two anchors same slot                   ❌ NEVER
Anchor + unrelated text same slot       ❌ NEVER
```

### VISUAL ANCHOR ANTI-OVERLAP ZONES

When a visual anchor is active, these zones are RESERVED:

```
ANCHOR at ORIGIN:
  Reserved: x ∈ [-3.0, +3.0], y ∈ [-2.0, +2.0]
  Text must be: y > +2.3 OR y < -2.3

ANCHOR at RIGHT * 3.0:
  Reserved: x ∈ [+1.0, +5.5], y ∈ [-2.5, +2.5]
  Steps must be: x < +0.5

ANCHOR at DOWN * 1.2:
  Reserved: y ∈ [-3.0, +0.0]
  Expression rows must be: y > +0.3
```

IRON LAW — NEVER USE or ON MANIM VECTOR ARGUMENTS (NO EXCEPTIONS)

Manim position arguments (UP, DOWN, LEFT, RIGHT, ORIGIN and any
linear combination) are numpy arrays. Python's or operator calls
bool() on them, which raises:
  ValueError: The truth value of an array with more than one
  element is ambiguous.

CONSEQUENCES:
❌ NEVER write:   value = arg or default
❌ NEVER write:   value = arg if arg else default
✅ ALWAYS write:  value = arg if arg is not None else default
✅ ALWAYS write:  value = default if arg is None else arg

APPLIES TO:
  StepManager.__init__(start_anchor=None)
  Any helper that accepts an optional position argument
  Any function with signature f(pos=None) where pos may be a numpy array

IRON LAW — NEVER POSITION HIGHLIGHTS BY ARITHMETIC ON MathTex.width
(NO EXCEPTIONS)

MathTex renders as a single compiled texture. You cannot reliably
locate a substring by doing:
  overlay.move_to(expr.get_right() + LEFT * overlay.width / 2)
This always produces overlapping or misaligned highlights.

CORRECT METHODS for highlighting part of an expression:

METHOD A — Split into separate MathTex objects (PREFERRED):
  t1  = math_obj(r"23", ...)
  op  = math_obj(r"-", ...)
  t2  = math_obj(r"10 \times 2", ...)
  expr_row = VGroup(t1, op, t2).arrange(RIGHT, buff=0.15)
  self.play(t2.animate.set_color(ORANGE_HL))

METHOD B — Use MathTex subobject indexing:
  expr = MathTex(r"23", r"-", r"10 \times 2", ...)
  self.play(expr[2].animate.set_color(ORANGE_HL))

❌ NEVER:  overlay.move_to(expr.get_right() + LEFT * x)
❌ NEVER:  overlay.move_to(expr.get_left()  + RIGHT * x)
❌ NEVER:  position any highlight object by arithmetic on parent width
✅ ALWAYS: split MathTex into separately-addressable parts when
           selective highlighting is needed

IRON LAW — NEVER BUILD WIDE SOLUTION ROWS AS SINGLE VGROUPS

Any solution row containing MORE THAN 4 MathTex objects arranged

MANDATORY WIDTH BUDGET PER ROW:
Safe area width = 12.22 units total
LEFT zone (steps) = max 6.0 units available
Each MathTex object approx 0.6-1.2 units at font_size=28

CONSEQUENCES:
❌ NEVER arrange more than 4 MathTex objects in one horizontal VGroup

❌ NEVER put two full expressions side-by-side in one add_step() row
✅ ALWAYS split wide rows into stacked sub-rows within a single
   VGroup passed to add_step() (Solution A from sub-row law)

FONT SIZE RULE FOR SIDE-BY-SIDE EXPRESSIONS:

IRON LAW — STEPMANAGER IS BLIND TO SUB-ROWS (NO EXCEPTIONS)

StepManager positions each new step using next_to(self.steps[-1], DOWN).
Sub-rows placed below a header via next_to() are NOT tracked by
StepManager. If you add more steps after sub-rows, the new steps
will be positioned below the HEADER — not below the sub-rows —
causing GUARANTEED overlap.

This is the #1 cause of step-on-step overlap in derivation sequences.

DIAGNOSTIC — how the bug occurs:
  mgr.add_step(hdr)           <- mgr.steps[-1] = hdr
  row1.next_to(hdr, DOWN)     <- mgr does NOT know row1
  row2.next_to(row1, DOWN)    <- mgr does NOT know row2
  mgr.add_step(s3)            <- s3 placed below hdr → OVERLAPS row1/row2

SOLUTION A — GROUP INTO ONE STEP (when ≤ 3 internal lines):
  line1 = VGroup(sin_lhs, frac_ac).arrange(RIGHT, buff=0.18)
  line2 = VGroup(cos_lhs, frac_bc).arrange(RIGHT, buff=0.18)
  full_step = VGroup(line1, line2).arrange(DOWN,
      aligned_edge=LEFT, buff=0.18)
  mgr.add_step(full_step)
  # StepManager now knows the full height of both lines
  # Next add_step() positioned below line2 → NO overlap

SOLUTION B — PHASE SPLIT (when 4+ total steps or complex sub-rows):
  mgr1 = StepManager(self, ...)
  mgr1.add_step(s1)
  mgr1.add_step(s2)
  mgr1.add_step(s3)

  # Phase transition — clean break
  mgr1.fadeout_all()
  for s in [s1, s2, s3]:
      if s in active_mobs: active_mobs.remove(s)
  self.wait(0.2)

  # Fresh StepManager — starts clean at anchor
  mgr2 = StepManager(self, ...)
  mgr2.add_step(s4)    # positioned at anchor — no overlap risk
  mgr2.add_step(s5)

PHASE SPLIT BOUNDARY RULE:
  Phase boundary = natural audio pause (between two bookmarks)
  Each phase: max steps = SAFE_LIMITS for chosen (font_size, buff)
  Each phase: StepManager starts fresh at anchor position

CONSEQUENCES:
❌ NEVER call mgr.add_step() after placing sub-rows via next_to()
❌ NEVER assume StepManager tracks anything not passed to add_step()
❌ NEVER place elements below a step using next_to() then add more steps
✅ ALWAYS use Solution A (group into one step) or Solution B (phase split)
✅ ALWAYS count total steps — if > SAFE_LIMITS, phase split is mandatory
✅ Every step in both mgr.steps AND active_mobs → clean ownership

IRON LAW — EVERY MOB ADDED TO SCENE MUST HAVE EXACTLY ONE
FADEOUT OWNER (NO EXCEPTIONS)

A mobject that is FadeIn'd but NOT owned by a FadeOut mechanism
becomes a GHOST — it persists across segment boundaries.

GHOST CONDITIONS (any one creates a ghost):
❌ mob added to active_mobs BUT removed before clear_and_transition()
   without a corresponding FadeOut
❌ mob FadeIn'd AFTER mgr.add_step() but NOT added to mgr.steps
   (StepManager's fadeout_all() will NOT fade it)
❌ mob added to active_mobs, then active_mobs.remove(mob) called
   WITHOUT self.play(FadeOut(mob)) first

CHECKMARK / ANNOTATION GHOST PREVENTION:
❌ NEVER create a checkmark as a standalone mob next_to a step
✅ ALWAYS embed checkmark INSIDE the step VGroup

FADEOUT OWNERSHIP RULES:
✅ If mob is in mgr.steps -> owned by mgr.fadeout_all() OR
   clear_and_transition()
✅ If mob is in active_mobs AND NOT in mgr.steps -> owned by
   clear_and_transition() only
✅ If doing manual phase fadeout -> build explicit list and FadeOut all

DOUBLE-TRACKING PREVENTION:
If you call mgr.fadeout_all() manually mid-segment:
  STEP 1: call mgr.fadeout_all()
  STEP 2: remove those mobs from active_mobs immediately
  STEP 3: clear_and_transition() finds active_mobs clean

If you do NOT call mgr.fadeout_all() manually:
  Keep steps in active_mobs — clear_and_transition() handles all.

IRON LAW — MANDATORY PRE-FADEIN OVERLAP CHECK (NO EXCEPTIONS)

next_to() and move_to() do NOT guarantee that a new element is
clear of all currently active elements. Overlap must be verified

MANDATORY PATTERN for every element introduction:

PREFERRED SHORTHAND:
  safe_fadein(self, mob, active_mobs, name="element_name")
  safe_create(self, mob, active_mobs, name="element_name")

CONSEQUENCES:
❌ NEVER call self.play(FadeIn(mob)) without steps 2-4 above
❌ NEVER call self.play(Create(mob)) without steps 2-4 above
❌ NEVER assume next_to() guarantees no overlap
✅ safe_fadein() / safe_create() are the DEFAULT for all
   element introductions

def _setup_poppins():
    base_dir  = os.path.dirname(os.path.abspath(__file__))
    fonts_dir = os.path.join(base_dir, ".fonts")
    os.makedirs(fonts_dir, exist_ok=True)
    base_url = (
        "https://raw.githubusercontent.com/google/fonts/main/ofl/poppins/"
    )
    fonts = {
        "Poppins-Regular.ttf":  base_url + "Poppins-Regular.ttf",
        "Poppins-Bold.ttf":     base_url + "Poppins-Bold.ttf",
        "Poppins-Italic.ttf":   base_url + "Poppins-Italic.ttf",
        "Poppins-SemiBold.ttf": base_url + "Poppins-SemiBold.ttf",
    }
    for fname, url in fonts.items():
        path = os.path.join(fonts_dir, fname)
        if not os.path.exists(path):
            try:
                urllib.request.urlretrieve(url, path)
            except Exception as e:
                print(f"Could not download {fname}: {e}")
                continue
        try:
            manimpango.register_font(path)
        except Exception:
            pass

def make_concept_card(text_str, position=ORIGIN,
                      font_size=26, max_chars=55):
    if len(text_str) > max_chars:
        words = text_str.split()
        lines, cur = [], ""
        for w in words:
            if len(cur) + len(w) + 1 <= max_chars:
                cur += (" " if cur else "") + w
            else:
                lines.append(cur); cur = w
        if cur: lines.append(cur)
        text_str = "\n".join(lines)
    txt = Text(text_str, font="Poppins", font_size=font_size,
               color=PURPLE)
    bg = RoundedRectangle(
        corner_radius=0.2, width=min(txt.width+0.8, 10.5),
        height=txt.height+0.4, fill_color=WHITE, fill_opacity=0.85,
        stroke_color=PALE_PURPLE, stroke_width=1.5)
    bg.move_to(position)
    txt.move_to(bg.get_center())
    return VGroup(bg, txt)


def make_bullet_point(text_str, position=ORIGIN,
                      font_size=26, max_chars=52):
    if len(text_str) > max_chars:
        words = text_str.split()
        lines, cur = [], ""
        for w in words:
            if len(cur) + len(w) + 1 <= max_chars:
                cur += (" " if cur else "") + w
            else:
                lines.append(cur)
                cur = w
        if cur:
            lines.append(cur)
        text_str = "\n".join(lines)
    dot = Text("\u2022", font="Poppins",
               font_size=font_size + 4, color=ORANGE_HL)
    txt = Text(text_str, font="Poppins",
               font_size=font_size, color=PURPLE)
    row = VGroup(dot, txt).arrange(RIGHT, buff=0.25,
                                   aligned_edge=UP)
    row.move_to(position)
    return row


def make_grid_overlay(w, h, cell=0.5, color=PALE_PURPLE):
    cols, rows_n = int(w/cell), int(h/cell)
    cells = VGroup()
    for r in range(rows_n):
        for c in range(cols):
            sq = Rectangle(width=cell, height=cell,
                          fill_color=color, fill_opacity=0.15,
                          stroke_color=PURPLE, stroke_width=0.5)
            sq.move_to(RIGHT*(c+0.5)*cell + DOWN*(r+0.5)*cell)
            cells.add(sq)
    cells.move_to(ORIGIN)
    return cells


def make_tape_diagram(total, active, cw=1.2, ch=0.8):
    blocks = VGroup()
    for i in range(total):
        is_a = i < active
        b = Rectangle(width=cw, height=ch, color=PURPLE,
                      stroke_width=2.5,
                      fill_color=ORANGE_HL if is_a else PALE_PURPLE,
                      fill_opacity=0.8 if is_a else 0.3)
        blocks.add(b)
    blocks.arrange(RIGHT, buff=0)
    if blocks.width > 8.0:
        blocks.scale(8.0 / blocks.width)
    top_br = Brace(VGroup(*list(blocks)[:active]), UP, color=ORANGE_HL)
    top_lbl = math_obj(str(active), color=ORANGE_HL,
                       font_size=28).next_to(top_br, UP, buff=0.1)
    bot_br = Brace(blocks, DOWN, color=PURPLE)
    bot_lbl = math_obj(str(total), font_size=28
                       ).next_to(bot_br, DOWN, buff=0.1)
    return {"blocks": blocks,
            "diagram": VGroup(blocks, top_br, top_lbl,
                              bot_br, bot_lbl)}

              beam.get_left()+RIGHT*0.4+DOWN*0.4,
              color=PURPLE, stroke_width=3)
    rp = Line(beam.get_right()+LEFT*0.4+DOWN*0.4,
              beam.get_right()+RIGHT*0.4+DOWN*0.4,
              color=PURPLE, stroke_width=3)
    ls = Line(beam.get_left(), lp.get_center(),
              color=PURPLE, stroke_width=1.5)
    rs = Line(beam.get_right(), rp.get_center(),
              color=PURPLE, stroke_width=1.5)
    g = VGroup(beam, pivot, post, base, lp, rp, ls, rs)
    return {"scale_group": g, "beam": beam, "pivot": pivot,
            "left_anchor":  lp.get_top()+UP*0.35,
            "right_anchor": rp.get_top()+UP*0.35}

def make_arrow_annotation(mob, text_str, direction=UP, color=ORANGE_HL):

def clear_and_transition(scene, active_mobs, new_bg,
                         ft=0.8, buf=0.2, settle=0.1):
    if active_mobs:
        scene.play(*[FadeOut(m) for m in active_mobs], run_time=ft)
    scene.wait(buf)
    scene.camera.background_color = new_bg
    scene.wait(settle)


SAFE_L, SAFE_R = -6.11, 6.11
SAFE_T, SAFE_B = 3.25, -3.25


def check_safe_margins(mob, name="obj"):
    ok = True
    if mob.get_left()[0]   < SAFE_L: ok = False
    if mob.get_right()[0]  > SAFE_R: ok = False
    if mob.get_top()[1]    > SAFE_T: ok = False
    if mob.get_bottom()[1] < SAFE_B: ok = False
    if not ok:
        print(f"MARGIN WARNING: {name}")
        clamp_to_safe_area(mob)
    return ok


def clamp_to_safe_area(mob):
    sx, sy = 0, 0
    if   mob.get_left()[0]   < SAFE_L: sx = SAFE_L - mob.get_left()[0]
    elif mob.get_right()[0]  > SAFE_R: sx = SAFE_R - mob.get_right()[0]
    if   mob.get_bottom()[1] < SAFE_B: sy = SAFE_B - mob.get_bottom()[1]
    elif mob.get_top()[1]    > SAFE_T: sy = SAFE_T - mob.get_top()[1]
    if sx or sy: mob.shift(RIGHT*sx + UP*sy)
    return mob


def fit_stack_to_safe_area(vgroup):
    max_h = (SAFE_T - SAFE_B) - 0.5
    if vgroup.height > max_h:
        vgroup.scale_to_fit_height(max_h)
    return vgroup


def check_y_gap(new_mob, existing_mobs, min_gap=0.3, name="new_mob"):
    for mob in existing_mobs:
        if isinstance(mob, VGroup) and len(mob) == 0:
            continue
        new_bottom = new_mob.get_bottom()[1]
        new_top    = new_mob.get_top()[1]
        mob_bottom = mob.get_bottom()[1]
        mob_top    = mob.get_top()[1]
        if new_bottom < mob_top and new_top > mob_bottom:
            shift_needed = mob_top + min_gap - new_bottom
            new_mob.shift(UP * shift_needed)
            print(f"WARNING: '{name}' overlapped. "
                  f"Shifted UP by {shift_needed:.2f}")
        elif (new_bottom >= mob_top and
              (new_bottom - mob_top) < min_gap):
            shift_needed = min_gap - (new_bottom - mob_top)
            new_mob.shift(UP * shift_needed)
            print(f"WARNING: '{name}' too close. "
                  f"Shifted UP by {shift_needed:.2f}")
    return new_mob


def has_overlap(a, b, margin=0.15):
    return (a.get_left()[0]-margin   < b.get_right()[0] and
            a.get_right()[0]+margin  > b.get_left()[0]  and
            a.get_bottom()[1]-margin < b.get_top()[1]   and
            a.get_top()[1]+margin    > b.get_bottom()[1])


def resolve_overlaps(new_mob, active_mobs, name="new"):
    for mob in active_mobs:
        if isinstance(mob, VGroup) and len(mob) == 0:
            continue
        if has_overlap(new_mob, mob):
            shift_y = mob.get_bottom()[1] - new_mob.get_top()[1] - 0.2
            new_mob.shift(DOWN * abs(shift_y))
            if new_mob.get_bottom()[1] < SAFE_B:
                new_mob.shift(UP * abs(shift_y))
                shift_x = mob.get_right()[0] - new_mob.get_left()[0] + 0.3
                new_mob.shift(RIGHT * shift_x)
            print(f"OVERLAP FIX: {name} repositioned")
    clamp_to_safe_area(new_mob)
    return new_mob


def safe_fadein(scene, mob, active_mobs, name="obj", run_time=0.7):
    check_safe_margins(mob, name)
    check_y_gap(mob, active_mobs, name=name)
    resolve_overlaps(mob, active_mobs, name)
    scene.play(FadeIn(mob), run_time=run_time)
    active_mobs.append(mob)
    return mob


def safe_create(scene, mob, active_mobs, name="obj", run_time=1.0):
    check_safe_margins(mob, name)
    resolve_overlaps(mob, active_mobs, name)
    scene.play(Create(mob), run_time=run_time)
    active_mobs.append(mob)
    return mob


class StepManager:
    LIMITS = {(32,0.4):3, (28,0.3):4, (24,0.25):5, (20,0.2):6}

    def __init__(self, scene, start_anchor=None,
                 font_size=28, buff=0.3):
        self.scene  = scene
        self.steps  = []
        self.fs     = font_size
        self.buff   = buff
        self.max    = self.LIMITS.get((font_size, buff), 4)
        self.anchor = (
            start_anchor if start_anchor is not None
            else (UP * 2.0 + LEFT * 3.5)
        )

    def add_step(self, mob, run_time=0.7):
        if len(self.steps) >= self.max:
            print(f"WARNING: StepManager at safe limit ({self.max}).")
        if self.steps:
            mob.next_to(self.steps[-1], DOWN,
                        aligned_edge=LEFT, buff=self.buff)
            self.scene.play(
                *[s.animate.set_opacity(0.4) for s in self.steps],
                FadeIn(mob), run_time=run_time)
        else:
            mob.move_to(self.anchor)
            self.scene.play(FadeIn(mob), run_time=run_time)
        self.steps.append(mob)
        if mob.get_bottom()[1] < SAFE_B:
            print("WARNING: step below safe area")
        return mob

    def highlight_last(self):
        if self.steps:
            self.scene.play(
                self.steps[-1].animate.set_color(ORANGE_HL),
                run_time=0.5)

    def get_all(self):
        return VGroup(*self.steps)

    def fadeout_all(self, rt=0.8):
        if self.steps:
            self.scene.play(*[FadeOut(s) for s in self.steps],
                            run_time=rt)
            self.steps.clear()

## APPENDIX C — BUG PREVENTION TABLE

| Bug                          | Wrong                                        | Correct                                                          |
|------------------------------|----------------------------------------------|------------------------------------------------------------------|
| Background not a wipe        | camera.bg = color (expecting clear)          | FadeOut all -> wait -> change bg                                 |
| Two slide types one block    | title + content in one voiceover             | separate voiceover block per slide type                          |
| Labels overlap shape         | label.next_to(shape, DOWN, buff=0.1)         | buff >= 0.3, arrow OUTSIDE shape                                 |
| Steps overlap figure         | steps at CENTER, figure at CENTER            | steps LEFT*3.5, figure RIGHT*3.0                                 |
| Double displacement          | .shift() + .animate.shift()                  | ONE strategy only                                                |
| Title has voiceover block    | voiceover block in show_title()              | NO voiceover in show_title(); greeting in first content segment  |
| Title hold too long          | self.wait(3.0) delays content sync           | self.wait(2.0) — always 2 seconds, never 3                      |
| Equations out of sync        | audio starts on title, visuals on content    | audio starts on same slide as visuals — always                   |
| Audio over title card        | greeting plays while title still showing     | title is silent; greeting is first line of content voiceover     |
| Fraction spoken wrong        | "three quarters"                             | "three over four"                                                |
| LaTeX fraction invisible     | MathTex(r"\frac{a}{b}")                      | make_fraction("a", "b")                                          |
| Unicode blank box            | Text("theta")                                | MathTex(r"\theta")                                               |
| Step overlaps sub-rows       | mgr.add_step() after next_to() sub-rows      | Group into one VGroup step or phase-split with fadeout_all()     |
| Sub-rows invisible to mgr    | sub-rows via next_to() between add_step()     | Solution A: group into single step VGroup                       |
| Too many steps one phase     | 6 steps at font_size=28                      | Phase split: fadeout_all() + fresh StepManager                   |
| Phase split missing cleanup  | fadeout_all() without active_mobs removal    | fadeout_all() + remove from active_mobs + wait(0.2)              |
| Overlap not caught at runtime| self.play(FadeIn(mob)) directly              | safe_fadein(self, mob, active_mobs) — always                     |
| Diagram overlaps annotation  | tape at ORIGIN with expr rows above          | tape at DOWN*1.2; verify gap >= 0.6 units                        |
| Stack overflows frame        | 6 steps at font_size=32                      | compute height first; phase split                                |
| Highlight overlay misaligned | overlay positioned by MathTex width math     | Split MathTex into separate objects                              |
| Ghost after FadeOut          | FadeOut(parent, child)                       | FadeOut(parent) only                                             |
| numpy array boolean test     | start_anchor or default                      | start_anchor if start_anchor is not None else default            |
| Question text not cleared    | StepManager starts with q_text visible       | FadeOut all q_texts before first mgr.add_step()                  |
| Blank screen during audio    | Audio plays with no visual on screen         | Every sentence has a visual anchor (Type 1-6)                    |
| Text anchor when visual ok   | concept card for "rectangle has 4 sides"     | Draw the rectangle (Type 1) — text card forbidden here           |
| Anchor overlaps steps        | anchor at ORIGIN during solution             | anchor at SLOT_FIGURE_R; steps at SLOT_STEPS                     |
| Two anchors same slot        | shape + diagram both at ORIGIN               | ONE anchor per slot; phase split if needed                       |

## APPENDIX D — CONCEPT ANIMATION PATTERNS (ANCHOR-ENHANCED)

PATTERN A — OBJECT + ACTION (verb: split, divide, cut, become)
  ANCHOR: Type 1 (Geometric) or Type 3 (Transformation)
  ANIMATION: Create shape → animate the action → show result
  EXAMPLE: "split the rectangle" → rectangle splits into two triangles

PATTERN B — CAUSE -> EFFECT (has "so/therefore/notice/means")
  ANCHOR: Type 3 (Transformation) with ValueTracker
  ANIMATION: Change input → watch output change in real-time
  EXAMPLE: "double the radius so area quadruples" → circle grows, area updates

PATTERN C — SIDE BY SIDE CONTRAST (compares two cases)
  ANCHOR: Type 1 (Geometric) × 2, placed LEFT*3 and RIGHT*3
  ANIMATION: Both appear, then differences highlighted
  EXAMPLE: "square vs rectangle" → both shapes with labeled differences

PATTERN D — NUMBER ROLE ANNOTATION (explains what a number means)
  ANCHOR: Type 4 (Annotation) on existing expression or figure
  ANIMATION: Arrow/highlight appears on the specific part being explained
  EXAMPLE: "the 5 means five groups" → arrow from "5" to label "groups"

PATTERN E — CONCEPT ECHO (closing sentence restating concept)
  ANCHOR: Type 6 (Text) — concept card with the restated concept
  ANIMATION: FadeIn concept card below the visual anchor
  EXAMPLE: "so area equals length times width" → card with "A = l × w"

PATTERN F — SEQUENTIAL EXPRESSION BUILDING
  ANCHOR: Type 5 (Sequential Build)
  ANIMATION: Expression builds piece by piece, each piece at a bookmark
  EXAMPLE: "start with A, equals, l times w" → "A" → "=" → "l × w"

PATTERN G — PART-WHOLE VISUALIZATION (NEW)
  ANCHOR: Type 2 (Diagram) — tape diagram or bar model
  ANIMATION: Whole shown first, then parts highlighted progressively
  EXAMPLE: "3 out of 5 parts" → 5 blocks appear, then 3 turn orange

PATTERN H — DEFINITION + EXAMPLE PAIR (NEW)
  ANCHOR: Type 6 (Text) + Type 1/2 (Visual) — stacked
  ANIMATION: Definition card appears UP*1.5, then visual example at ORIGIN
  EXAMPLE: "A polygon is a closed shape" → card UP, then pentagon drawn below

If NONE of Patterns A-H applies → make_concept_card() with verbatim
transcript text (Pattern E fallback — ALWAYS the last resort).
